# نمایندگی‌های ما — قالب تک‌صفحه‌ای + بک‌اند

قالب تک‌صفحه‌ای، راست‌چین و واکنش‌گرا برای معرفی شبکه نمایندگی‌های یک برند در
استان‌های ایران، با نقشه تعاملی و فرم چندمرحله‌ای درخواست نمایندگی — به‌همراه
یک بک‌اند واقعی (PHP + MySQL) برای همان فرم و فهرست نمایندگان، و یک پنل
مدیریت برای بررسی درخواست‌ها و مدیریت نمایندگان. فرانت‌اند بدون نیاز به
فریم‌ورک یا مرحله بیلد است — فقط HTML/CSS/JS خالص؛ بک‌اند هم PHP ساده (بدون
فریم‌ورک/Composer) است تا روی هر هاست اشتراکی معمولی (cPanel و مشابه) مستقیماً
اجرا شود.

## ساختار پروژه

```
index.html                        صفحه اصلی (تک‌صفحه با اسکرول به بخش‌ها)
representatives.html              فهرست نمایندگان یک استان — از نقشه یا representatives.html?province=<slug> باز می‌شود
assets/css/style.css              تمام استایل‌ها و توکن‌های طراحی
assets/js/main.js                 منطق ناوبری، نقشه، انیمیشن، فرم، آکاردئون (فقط index.html)
assets/js/representatives.js      منطق صفحه فهرست نمایندگان: جست‌وجو، فیلتر شهر/رسته، رندر کارت‌ها
assets/js/provinces-data.js       نام فارسی، مرکز استان و مختصات نقشه هر استان (تعداد نماینده از بک‌اند می‌آید)
assets/js/representatives-data.js فراخوانی API برای فهرست نمایندگان + نمونه‌داده جای‌گیر برای وقتی بک‌اند بالا نیست
assets/svg/iran-map.svg           نقشه ۳۱ استان ایران (ISC License)
scripts/generate-map-labels.mjs   بازتولید مختصات برچسب نام استان‌ها روی نقشه (فقط اگر iran-map.svg تغییر کند)

schema.sql                        ساختار دیتابیس (سه جدول: admins, representatives, applications)
api/                               endpoint های عمومی JSON که فرانت‌اند صدا می‌زند
  _config.example.php               ← کپی کنید به _config.php و اطلاعات دیتابیس واقعی را وارد کنید
  _db.php, _auth.php, _provinces.php  کمک‌کدهای مشترک (مستقیم قابل درخواست نیستند)
  provinces.php                     GET  → تعداد نماینده فعال هر استان
  representatives.php               GET  → فهرست نمایندگان یک استان
  applications.php                  POST → ثبت درخواست نمایندگی از فرم سایت
admin/                             پنل مدیریت (نیازمند ورود)
  setup.php                         ساخت اولین حساب مدیر (فقط یک‌بار قابل استفاده)
  login.php, logout.php
  index.php                        داشبورد
  applications.php, application.php   فهرست و بررسی درخواست‌ها (تأیید/رد)
  representatives.php, representative-form.php, representative-delete.php   مدیریت نمایندگان
uploads/applications/              مدارک بارگذاری‌شده از فرم (خودکار ساخته می‌شود؛ داخل گیت نیست)
```

## اجرای محلی

**فرانت‌اند به‌تنهایی** (بدون بک‌اند، با نمونه‌داده جای‌گیر برای فهرست نمایندگان):

```bash
python3 -m http.server 8080
# سپس مرورگر را باز کنید: http://localhost:8080
```

نقشه با `fetch()` بارگذاری می‌شود، پس باید از طریق یک وب‌سرور محلی اجرا شود
(نه مستقیم با `file://`).

**با بک‌اند واقعی** (نیازمند PHP و MySQL/MariaDB نصب‌شده):

```bash
# ۱) یک دیتابیس بسازید و schema.sql را ایمپورت کنید
mysql -u root -e "CREATE DATABASE namyandegi CHARACTER SET utf8mb4;"
mysql -u root namyandegi < schema.sql

# ۲) فایل تنظیمات را بسازید و اطلاعات دیتابیس را وارد کنید
cp api/_config.example.php api/_config.php
# ... api/_config.php را ویرایش کنید ...

# ۳) سرور توسعه PHP را از ریشه پروژه اجرا کنید
php -S localhost:8080

# ۴) به admin/setup.php بروید و اولین حساب مدیر را بسازید
```

## استقرار روی هاست اشتراکی (cPanel/PHP)

۱. کل پوشه پروژه را در ریشه ساب‌دامین (`public_html` همان ساب‌دامین) آپلود کنید — چیزی
   کامپایل نمی‌شود، همین فایل‌ها مستقیم اجرا/سرو می‌شوند.
۲. از cPanel → **MySQL Databases** یک دیتابیس و یک کاربر دیتابیس بسازید و آن
   کاربر را با دسترسی «ALL PRIVILEGES» به دیتابیس متصل کنید.
۳. از phpMyAdmin، محتوای `schema.sql` را روی همان دیتابیس ایمپورت کنید.
۴. فایل `api/_config.example.php` را کپی کنید به `api/_config.php` (مثلاً از
   File Manager) و مقادیر واقعی دیتابیس (نام/کاربر/رمز — معمولاً با پیشوند نام
   اکانت هاست، مثل `myuser_namyandegi`) و ایمیل اطلاع‌رسانی درخواست‌ها را در
   آن وارد کنید.
۵. به آدرس `https://دامنه‌شما/admin/setup.php` بروید و اولین حساب مدیر را
   بسازید — این صفحه فقط یک‌بار کار می‌کند (بعد از ساخت اولین حساب، خودش را
   غیرفعال می‌کند)، ولی برای امنیت بیشتر بعداً می‌توانید خودِ فایل
   `admin/setup.php` را هم از روی هاست حذف کنید.
۶. پوشه `uploads/applications/` باید توسط وب‌سرور قابل‌نوشتن باشد (معمولاً
   دسترسی ۷۵۵ روی هاست‌های اشتراکی کافی است؛ اگر آپلود مدرک با خطا مواجه شد،
   دسترسی این پوشه را بررسی کنید).
۷. به `admin/login.php` وارد شوید و از داشبورد استفاده کنید.

**نکته امنیتی:** چون فرم ورود پنل مدیریت رمز عبور واقعی رد و بدل می‌کند،
حتماً HTTPS را روی ساب‌دامین فعال کنید (اکثر هاست‌های ایرانی همین حالا
Let's Encrypt رایگان دارند).

**نکته مهم درباره کش مرورگر/هاست:** فایل‌های `assets/css/style.css` و
`assets/js/*.js` در `index.html` و `representatives.html` با یک پارامتر
نسخه صدا زده می‌شوند (مثلاً `main.js?v=1.1`)، دقیقاً برای اینکه بعد از هر
آپدیت، مرورگر بازدیدکننده (یا کش سمت هاست/CDN) نسخه قدیمی را از حافظه سرو
نکند — چون همین باعث می‌شود رفتار سایت با نسخه‌ای که تست کرده‌اید فرق کند
(مثلاً تول‌تیپ نقشه رفتار قدیمی/باگ‌دار نشان دهد چون JS جدید واقعاً بارگذاری
نشده). **هر بار که فایل‌های `assets/css` یا `assets/js` را روی هاست آپدیت
می‌کنید، عدد `v=` را در همه‌ی `<link>`/`<script>` مربوطه در `index.html` و
`representatives.html` یکی زیاد کنید** (مثلاً `1.1` → `1.2`)، تا مرورگرها
مجبور شوند نسخه تازه را بگیرند.

## چیزهایی که باید پیش از انتشار جایگزین کنید

| مورد | محل |
|---|---|
| نام برند و لوگو | `.brand` در `index.html`، `representatives.html` و `admin/_layout_top.php` |
| اطلاعات تماس فوتر و بنر CTA | بخش `footer-contact` و لینک `tel:` |
| نظرات نمایندگان | بخش `#testimonials` در `index.html` — نمونه/جای‌گیر است |
| اطلاعات واقعی دیتابیس | `api/_config.php` (از روی `_config.example.php` بسازید — گیت‌ایگنور شده) |
| نمایندگان واقعی | از پنل مدیریت (`admin/representatives.php`) اضافه کنید؛ دیگر نیازی به دستکاری کد نیست |

## نکات فنی

- **فونت:** Vazirmatn از Google Fonts، با `font-display: swap`.
- **انیمیشن:** GSAP (فقط core، بدون پلاگین) برای ورود هیرو و افکت رسم‌شدن
  مرز استان‌ها روی نقشه؛ برای بقیه بخش‌ها از `IntersectionObserver` استفاده
  شده. همه انیمیشن‌ها با `prefers-reduced-motion` غیرفعال/ساده می‌شوند.
- **دسترس‌پذیری:** فوکوس قابل مشاهده، برچسب‌های ARIA روی نقشه و فرم، ناوبری
  کامل با کیبورد (Tab/Enter/Space/Escape روی نقشه)، خطاهای فرم متصل به فیلد.
- **نقشه:** داده مسیر SVG از پکیج متن‌باز `iran-svg-map` (لایسنس ISC) گرفته
  شده؛ اعتبار در کامنت بالای `assets/svg/iran-map.svg` ذکر شده است. جانمایی و
  اندازه ۳۱ استان با موقعیت جغرافیایی واقعی آن‌ها تطبیق داده و تأیید شده
  (نسبت به هم، شرق/غرب و شمال/جنوب صحیح است). نام هر استان مستقیماً روی نقشه
  نوشته شده — نقطه لنگر هر برچسب (`cx/cy/r` در `provinces-data.js`) با یک
  الگوریتم «دورترین نقطه از مرز» محاسبه شده، نه مرکز باکس/سطح، چون برای
  استان‌های باریک یا مقعر (تهران، سمنان، گیلان، مازندران…) مرکز ساده بیرون از
  شکل یا روی استان همسایه می‌افتد. نقشه در بالای صفحه یک ردیف کامل و بزرگ را
  اشغال می‌کند (نه نصف صفحه کنار متن)؛ روی هر استان دارای نماینده، یک پین
  آبی با تعداد نمایندگان فعال همان استان هم نمایش داده می‌شود (مستقیم روی
  نقشه، بدون نیاز به کلیک) — استان‌های بدون نماینده فقط نام را نشان می‌دهند.
- **صفحه نمایندگان:** فهرست از `api/representatives.php` می‌آید (اگر در
  دسترس نباشد، به نمونه‌داده جای‌گیر برمی‌گردد)؛ جست‌وجو (نام/شهر) و فیلتر
  شهر/رسته شغلی روی همان نتیجه، کاملاً سمت کلاینت است. سه حالت جدا مدیریت
  می‌شود: استان بدون نماینده واقعی (دعوت به ثبت‌نام)، فیلتر بدون نتیجه (دکمه
  پاک‌کردن فیلترها)، و بدون پارامتر `province` معتبر در آدرس.
- **بک‌اند:** PHP خام (بدون فریم‌ورک) + PDO/MySQL، بدون هیچ وابستگی خارجی —
  فقط `php-pdo-mysql` که روی هر هاست معمولی از قبل فعال است. رمزهای عبور با
  `password_hash`/`password_verify` هش می‌شوند، همه کوئری‌ها Prepared
  Statement هستند، فرم‌های پنل مدیریت CSRF token دارند، و آپلود مدرک هم با
  بررسی واقعی نوع فایل (نه فقط پسوند) و هم با نام‌گذاری تصادفی ذخیره می‌شود.
